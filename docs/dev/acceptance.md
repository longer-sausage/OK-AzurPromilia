# 验收手册：每条功能怎么点、该看到什么

[功能对照表](feature_map.md) 回答「这条需求落在哪个文件」；**这份手册回答「我怎么自己试一遍」**。
不需要读代码，照着点就能确认。

前置：`uv run python main_debug.py` 打开程序（或安装包直接运行）。没有游戏窗口时，
下面标注「需要游戏」的步骤只能看到界面与配置，看不到实际动作——但**界面是否正常、配置是否保存**
都可以先验。

> 有 `🖱️` 的是纯界面操作；`📄` 的是改文件/跑命令；`🎮` 的需要游戏窗口。

---

## 一、识别与恢复（工具与诊断页）

| # | 做什么 | 应该看到 |
|---|--------|----------|
| 1 | 🖱️ 让某个任务失败一次（例如断网后跑「每日委托」），然后打开「工具与诊断」 | 「失败帧」列表多了一条，带时间/任务名/分辨率；点一条能预览画面 |
| 2 | 🖱️ 选中一条失败帧 → 点「复测全部模板」 | 几秒内出现按分数排序的表：命中项标「命中」，接近阈值的标「差一点」；顶部写「共 N 个模板，命中 M 个，耗时 x 秒」（1080p 约 5 秒） |
| 3 | 🖱️ 上面那条失败帧标题里有「已遮挡」 | 说明 UID 遮挡对失败帧也生效了（若没开遮挡则不会出现该标记） |
| 4 | 🖱️ 「工具与诊断 → 素材包」选一个 zip → 安装 | 提示已安装，并刷新模板缓存（任务正在跑时会提示「这一次识别可能漏检」） |
| 5 | 🖱️ 「全局配置 → 自动化策略」把「单步超时」改成 3 秒 → 跑一个需要等画面的任务 | 该任务在识别等待超过 3 秒后失败（而不是一直等） |
| 6 | 🖱️ 同页打开「低配模式」 | 等价的超时按 ×1.5 放宽；识别阈值**不变** |
| 7 | 🖱️ 同页把「失败后自动返回主菜单」打开、次数填 2 → 让任务失败 | 日志出现返回主菜单的动作，最多 2 次 |

## 二、日常与流程编排

| # | 做什么 | 应该看到 |
|---|--------|----------|
| 8 | 🖱️ 「一条龙顺序」页拖动调整子任务顺序 → 保存 | 重启程序后顺序仍然是改过的；「一键日常」按新顺序执行 |
| 9 | 🖱️ 同页选中一项 | 右侧显示它**与默认值不同**的参数摘要（可打开该任务的配置文件） |
| 10 | 🖱️ 「流程与队列」页选中「周常活跃奖励」→ 运行 | 流程逐步执行（需要游戏）；日志每步一行 |
| 11 | 🖱️ 同页「从录制 JSON 生成」贴一段事件数组 | 生成流程预览：点击/按键/等待；右键与滚轮被计入「跳过 N 个无法表达的输入」 |
| 12 | 🖱️ 在「流程与队列 → 任务队列」给某一项设「预算分钟」并跑队列 | 到点后该项中止，日志写「超出时间预算，已中止」，且**不会再跑剩下的步骤**；`continue_on_error` 也不会让它硬撑下去 |
| 13 | 🖱️ 跑一个会中途失败的流程，勾「从断点继续」再跑一次 | 日志写「从断点继续：跳过前 N 个顶层步骤」；改了流程结构后再续跑 → 从头开始（旧断点被忽略） |
| 14 | 🖱️ 「配置档」存一份 → 改几个配置 → 应用该档 | 配置回到存档时的样子；`configs/profiles/.backup_*` 里有应用前的备份 |
| 15 | 📄 打开 `configs/profiles/<档名>/profile.json`，手改一个路径为 `../../evil.json` 后应用 | 提示「配置档里有越界路径」，**不会**写到 `configs/` 外面 |

## 三、离线工具（养成 / 抽卡 / 记账）

| # | 做什么 | 应该看到 |
|---|--------|----------|
| 16 | 🖱️ 「离线工具 → 养成」选一个角色 + 目标等级 → 点「计算」 | 材料单、体力折算、缺口（若有库存）；数字不为负 |
| 17 | 🖱️ 点「导出 CSV」（文件名手输「材料单」，不带扩展名） | 实际生成 `材料单.csv`，双击能用 Excel 打开 |
| 18 | 📄 `uv run python tools/import_growth.py --sample > 表.csv` 再改两行 → `--dry-run` | 打印解析出的条目与等级区间；写错 kind/数字会指出「第几行」 |
| 19 | 🖱️ 「离线工具 → 养成 → 导入数据」选那个 `.csv` | 提示导入成功、原文件已备份；条目下拉框立刻出现新条目 |
| 20 | 🖱️ 「抽卡分析」在「自定义概率表」里填 `150%` → 计算 | 提示「概率必须在 0%~100% 之间」，不会给出错误的期望抽数 |
| 21 | 🖱️ 把结算界面文字粘进「记账与报表」里的文本框 → 点记账 | 识别出「物品 ×数量」并记账；重复粘贴不会重复记账（页面上也写了：要直接识别画面请在任务列表跑「结算记账」） |

## 七、明确没做 / 需要你提供输入的

| 项 | 现状 | 你做什么 |
|----|------|----------|
| 危机讨伐 / 剧情委托 | 骨架流程已装，缺 3 个游戏内按钮模板 | 标模板（名字见流程里的 `crisis_hunt_*` / `story_commission_*`）或给截图 |
| 养成真实数值 | 内置是示例数据（导入通道已就绪：JSON 或 CSV） | 从 promilia.wiki 抄成 CSV 后导入 |
| 界面透明度 / 背景图 | ok-script 2.0.6 没有透明度 API | 无（不建议重写窗口合成） |
| 全屏十字线坐标拾取 | 现为「1 秒延时取点」 | 需要真机验证多屏/DPI 后再做覆盖层 |
| `assets/lang/home.json:little_bobo` | 只有简中译名 | 确认日/英/韩/繁/西的游戏内译名后补进该文件 |

## 附：这些「应该看到」是怎么被自动验证的

手册里的每一步，背后都有对应的离线测试（[功能对照表](feature_map.md) 的「测试」列）。
界面步骤本身靠 `tests/test_gui_tabs.py` 离屏构建 + 分流用例保证「点了不会炸」，
行为细节（分数、脱敏、回滚、断点失效、扩展名补全…）由各自的单元测试锁定。
所以这里的手工步骤主要是**看真实设备和真实画面**下的最终确认。
