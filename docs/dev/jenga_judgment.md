## 实际接触判定

`PlayableItemControllerComponet.CalculateSurfaceOverlap`（`0x183ED3820`）：

1. 从碰撞接触点取得法线。`abs(normal.y) < 0.5` 时返回 0，侧面碰撞不算搭建。
2. 两个 `BoxCollider` 分别选取朝向法线及反法线的面（`BestFace`）。
3. 将面的四角投影到接触平面（`ProjectFace`），取凸包（`ConvexHull`）。
4. 用 Sutherland–Hodgman 算法求两个凸多边形的交集（`SHClip`）。
5. 返回 `clamp01(交集面积 / min(面 A 面积, 面 B 面积))`。
   分母不大于 `1e-4` 时返回 0。

这是**碰撞盒接触面的面积比例**，不是截图轮廓宽度、屏幕包围框 IoU 或两个中心的距离。
耳朵、装饰、透视与塔身倾斜都会使视觉上重叠的比例不同于实际接触比例。

`HandleHouseCollision`（`0x183ED49D0`）在碰撞事件中计算比例；若指定了有效目标，
碰到的碰撞盒所属对象必须等于 `m_ValidTargetGo`，否则把比例和结果清零。
成功后刚体设为 kinematic，失败则弹开并启动销毁计时。因此事后看起来短暂落在塔上并不能证明成功。

## 分档及边界

蓝图规则：`90:2:1,80:2:1,60:1:1,50:1:1,0:0:0`。
`ParseScoreRules`（`0x183EE03E0`）将阈值除以 100；
`EvaluateByScoreRule`（`0x183EDB3E0`）按降序匹配 `ratio >= threshold`。

| 接触比例 | 蓝图最终结果 | 本次得分 |
| --- | --- | --- |
| ≥ 0.8 | Perfect = 2 | 1 |
| ≥ 0.5 且 < 0.8 | Good = 1 | 1 |
| < 0.5 | Miss = 0 | 0 |

边界注意：控制器自己的 `EvaluatePlacement`（`0x183ED4360`）先使用
`ratio <= m_MissThreshold` 判 Miss，再以 `ratio >= 0.8` 判 Perfect。
但存在有效蓝图规则时，回调 `<TriggerOnceControllerComponet>b__0`（`0x183EED870`）
会按上表重新计算并返回最终结果。因此不能把控制器的 `<= 0.5` 当作蓝图最终边界。

回调仅在最终结果为 Perfect 时设置 `m_PerfectFlags` 的对应位。
资料包提取的三星说明为“所有的图腾都被放置，并都是完美判定”；计数到达 20/20 或
出现 COMPLETE 不足以证明三星，必须检查最终三颗星。

进一步检查 `HandlePlayableOver`（`0x183EDC100`）：普通模式先读取结果字典中
Perfect（枚举 2）的数量，与最大雕像数比较；达到最大数才进入最高档分支。
否则再比较 Perfect + Good（枚举 1）的数量是否达到最大数。
`TotalSculptureCount`（`0x183EE6470`）则对所有结果增加下落计数，印证了
“HUD 达到 20/20”与“20 次 Perfect”是不同条件。

无限模式还有 `m_IsUnlimitedMode` 门控的强制失败分支：超过普通上限、接近硬上限时
按进度增加主动弹飞概率（`ForceMissAfterSuccess`），达到硬上限必触发。
不能把这个机制与普通 20 层挑战的视觉误判混为一谈。

## 实际运动

`CalculateFigure8Offset`（`0x183ED3770`）、`CalculateCurrentVelocity`（`0x183ED3690`）：

```text
phase += moveSpeed * fixedDeltaTime
localOffset = (horizontalRadius * sin(phase), verticalRadius * sin(2*phase), 0)
worldPosition = initialPosition + initialRotation * localOffset
worldVelocity = initialRotation * (
    horizontalRadius * moveSpeed * cos(phase),
    2 * verticalRadius * moveSpeed * cos(2*phase), 0)
```

轨迹是八字，纵向频率为横向两倍，不是资料中示例的椭圆。
蓝图值为 `moveSpeed=1.6`、横向半径 `1.25`、纵向半径 `0.4`。

`StopMovement`（`0x183ED6610`）保留当前速度的 x/z 分量，将 y 清零，
再投影去掉场景深度方向。**释放后横向速度不会归零。**

`SetControllerParams`（`0x183ED62C0`）把名为 `fallSpeed` 的参数写入
`m_GravityScale`，蓝图值 5 实际表示重力倍率。
`UpdateFallMove`（`0x183ED69A0`）每个固定步增加 `vy += -9.81 * gravityScale * dt`，
并以 `m_MaxFallSpeed` 限速；构造函数默认值为 `-10`。
忽略离散步与接触修正时，g = 49.05，约 0.2039 秒达到速度上限，之后匀速。
下落时间随释放高度变化，不能固定为 0.5 秒。

物理更新还有最多 4 个子步（最大步距 0.15）、扫掠检测、防穿透、0.01 的接触余量及
0.03 的近接触阈值（`PreventPenetration`，`0x183ED5230`）。应通过实机帧序列校准
离散步及输入延迟，不能只用连续公式就宣称稳定 Perfect。

## 2026-09-27：精确提取热更新碰撞盒
